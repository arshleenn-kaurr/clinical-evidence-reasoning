# Public tool dependency audit

Every `PUBLIC_CORE` / `PUBLIC_OPTIONAL` script, test, CI job, and README reproduction command was checked against `docs/public_release_manifest_draft.csv` for whether the files it actually reads at runtime are themselves `PUBLIC_CORE`/`PUBLIC_OPTIONAL`, or `LICENSE_REVIEW`/`ARCHIVAL_ONLY`/`SCRATCH_IGNORE`. "Required input" lists are read directly off each tool's source (package-root constants, `COHORTS`/`CASES` tables, `PATH_COLUMNS`), not guessed; the exact lines are cited.

**Finding: every existing full-archive tool requires at least one `LICENSE_REVIEW` (and, for `verify_hashes.py`, one `ARCHIVAL_ONLY`) input. None of them works unmodified against the stripped `dist/public_release_preview/`.** This is the problem Phase 5 fixes by adding a separate public-only path; it is not fixed by reclassifying restricted files.

## Files that *are* safe for a public validator to depend on

Cross-checked the same way, these required inputs are themselves `PUBLIC_CORE`/`PUBLIC_OPTIONAL` and so **can** be used by `scripts/validate_public_release.py`:

- `docs/public_release_manifest_draft.csv` and `dist/public_release_preview/MANIFEST.csv` (both PUBLIC_CORE/generated-and-shippable)
- `docs/result_provenance.csv` itself (PUBLIC_CORE) — its *contents* (not its restricted-path columns' *targets*) can be schema-checked
- Every `experiments/*/*/experiment_manifest.json` (PUBLIC_CORE)
- `analysis/posthoc_contrasts/*.csv`, `analysis/canonical_results_reference.md`, `analysis/*/accuracy_by_condition.csv` etc. (PUBLIC_CORE/PUBLIC_OPTIONAL — derived summary tables, not raw case text)
- `results/gemini_260_analysis.json`, `results/aligned_control_analysis.json` (PUBLIC_CORE — derived JSON, no case text)
- `scripts/reconstructed/*.py` and their own doc pages (`docs/figure1_reconstruction.md`, `docs/canonical_reference_reconstruction.md`) (PUBLIC_CORE)
- `CITATION.cff`, all `README.md`/`reproduce.md` files, `.github/workflows/*.yml` (PUBLIC_CORE)

## Conclusion

No existing script needed to be deleted or weakened. `scripts/validate_accepted_papers.py` remains the full scientific reproduction path and is documented as requiring the complete archive. A new, separate `scripts/validate_public_release.py` (Step 2) is required because no combination of flags on the existing tools makes them run on `PUBLIC_CORE`/`PUBLIC_OPTIONAL` files alone — their required inputs are structurally `LICENSE_REVIEW`.
